### 7장. 복수의 테이블 다루기

### 7-1. 집합 연산

SQL에서는 각 테이블을 **집합**, 테이블 내의 각 행(Row)을 **집합의 원소**로 간주하여 데이터 간의 집합 연산을 수행할 수 있다.

### UNION (합집합)

두 개의 `SELECT` 결과를 하나로 합칠 때 사용한다.

`UNION`은 기본적으로 **중복된 행을 제거(DISTINCT)** 한다.

```sql
SELECT a AS c FROM sample71_a
UNION
SELECT b AS c FROM sample71_b
ORDER BY c;
```

#### UNION 사용 시 주의사항

* 각 `SELECT` 명령의 **열 개수와 자료형이 서로 일치**해야 한다.
* 열 이름은 달라도 되지만, 열의 개수와 자료형은 서로 대응되어야 한다.
* 세미콜론(`;`)은 **가장 마지막 SELECT 문 뒤에만** 붙인다.

### ORDER BY 사용

`ORDER BY`는 `UNION`으로 결합한 전체 결과를 정렬하기 위해 **가장 마지막 SELECT 문 뒤에** 작성한다.

두 결과 집합의 열 이름이 서로 다르다면 `AS`를 사용하여 별칭(Alias)을 지정한 후 해당 별칭을 기준으로 정렬할 수 있다.

```sql
SELECT a AS c FROM sample71_a
UNION
SELECT b AS c FROM sample71_b
ORDER BY c;
```

### UNION ALL (중복 포함 합집합)

`UNION ALL`은 중복된 행을 제거하지 않고 두 결과 집합을 **그대로 합친다.**

```sql
SELECT * FROM sample71_a
UNION ALL
SELECT * FROM sample71_b;
```

`UNION`은 중복 여부를 확인하고 중복된 데이터를 제거하는 과정이 필요하다.

따라서 **중복이 발생하지 않는 것이 확실하거나 중복 제거가 필요하지 않은 경우에는 `UNION ALL`을 사용하는 것이 성능상 유리**하다.

### 교집합과 차집합

DBMS에 따라 지원하는 집합 연산자가 다르다.

MySQL에서는 `INTERSECT`(교집합)와 `EXCEPT`(차집합)를 직접 사용할 수 없다.

반면 Oracle, PostgreSQL 등 일부 DBMS에서는 `INTERSECT`와 `EXCEPT`를 지원한다.

### 7-2. 테이블 결합 (JOIN)

집합 연산이 데이터를 **세로 방향(행 증가)** 으로 확장한다면,

`JOIN`은 여러 테이블을 **가로 방향(열 확장)** 으로 결합하는 연산이다.

### 교차결합 (Cross Join)

교차결합은 두 테이블의 **모든 행을 서로 조합**하여 곱집합(Cartesian Product)을 만드는 방식이다.

예를 들어 테이블 A에 3개의 행, 테이블 B에 4개의 행이 있다면 총 `3 × 4 = 12개`의 행이 만들어진다.

```sql
SELECT *
FROM table_a, table_b;
```

`FROM` 절에 여러 테이블을 쉼표로 나열하면 별도의 결합 조건 없이 교차결합이 이루어진다.

### 내부결합 (Inner Join)

교차결합으로 만들어진 결과 중에서 **특정 결합 조건을 만족하는 행만 추출**하는 방식이다.

일반적으로 두 테이블의 PK와 FK처럼 서로 연관된 열을 기준으로 결합한다.

### 구식 스타일

```sql
SELECT 상품.상품명, 재고수.재고수
FROM 상품, 재고수
WHERE 상품.상품코드 = 재고수.상품코드
  AND 상품.상품분류 = '식료품';
```

### 표준 ANSI SQL 스타일

최근에는 `INNER JOIN`과 `ON`을 사용하는 방식을 주로 사용한다.

```sql
SELECT 상품.상품명, 재고수.재고수
FROM 상품
INNER JOIN 재고수
   ON 상품.상품코드 = 재고수.상품코드
WHERE 상품.상품분류 = '식료품';
```

`ON`에는 **두 테이블을 어떤 기준으로 연결할 것인지**를 작성하고, `WHERE`에는 **결합된 결과에서 어떤 데이터를 필터링할 것인지**를 작성한다.

### 기본키(PK)와 외래키(FK)

두 테이블의 동일한 값을 가진 열을 기준으로 데이터를 연결할 수 있다.

예를 들어 `상품` 테이블과 `재고수` 테이블에 공통적으로 `상품코드`가 존재한다면 이를 기준으로 두 테이블을 결합할 수 있다.

```text
상품.상품코드 = 재고수.상품코드
```

### 외부결합 (Outer Join)

외부결합은 **어느 한쪽 테이블을 기준으로 삼아**, 반대쪽 테이블에 결합 대상 데이터가 존재하지 않더라도 기준 테이블의 행을 모두 출력하는 방식이다.

결합되는 데이터가 없는 경우 해당 열은 `NULL`로 표시된다.

### LEFT JOIN

`LEFT JOIN`은 `JOIN`의 **왼쪽 테이블을 기준**으로 모든 행을 유지한다.

```sql
SELECT 상품.상품명, 재고수.재고수
FROM 상품
LEFT JOIN 재고수
  ON 상품.상품코드 = 재고수.상품코드;
```

상품 테이블에는 존재하지만 재고수 테이블에는 해당 상품코드가 없다면 재고수는 `NULL`로 출력된다.

### RIGHT JOIN

`RIGHT JOIN`은 `JOIN`의 **오른쪽 테이블을 기준**으로 모든 행을 유지한다.

```text
LEFT JOIN  → 왼쪽 테이블 기준
RIGHT JOIN → 오른쪽 테이블 기준
```

### 7-3. 관계형 모델 (Relational Model)

RDBMS는 **관계 수학의 관계대수(Relational Algebra)** 이론을 기반으로 설계되었다.

### 관계형 모델의 주요 용어

| 관계형 모델          | SQL         |
| --------------- | ----------- |
| 릴레이션 (Relation) | 테이블 (Table) |
| 속성 (Attribute)  | 열 (Column)  |
| 튜플 (Tuple)      | 행 (Row)     |

### 관계대수와 SQL의 대응

| 관계대수            | SQL          |
| --------------- | ------------ |
| 합집합             | `UNION`      |
| 차집합             | `EXCEPT`     |
| 교집합             | `INTERSECT`  |
| 곱집합             | `CROSS JOIN` |
| 선택 (Selection)  | `WHERE` 절    |
| 투영 (Projection) | `SELECT` 절   |
| 결합 (Join)       | `INNER JOIN` |

### 8장. 데이터베이스 설계

### 8-1. 스키마 및 객체 설계

데이터베이스 설계란 스키마 내에 **테이블, 인덱스, 뷰 등의 구조를 정의**하는 과정을 말한다.

### 논리명과 물리명

**논리명**은 설계서나 업무에서 사용하는 한글 또는 직관적인 명칭이다.

```text
주문테이블
상품코드
고객번호
```

**물리명**은 실제 DB 엔진에서 `CREATE TABLE` 등의 SQL문을 작성할 때 사용하는 이름이다.

```text
orders
product_id
customer_id
```

### 자료형과 길이 선택

데이터의 특성에 따라 적절한 자료형을 선택해야 한다.

### 수치형과 문자열형

숫자로 계산해야 하는 데이터는 일반적으로 수치형을 사용한다.

반면 다음과 같은 데이터는 숫자로만 구성되어 있어도 문자열형을 고려해야 한다.

* 전화번호
* 상품코드
* 우편번호
* 앞자리가 `0`으로 시작하는 번호

예를 들어 전화번호를 수치형으로 저장하면 앞의 `0`이 사라질 수 있기 때문에 문자열형으로 저장하는 것이 적절하다.

### CHAR와 VARCHAR

| 자료형       | 특징              |
| --------- | --------------- |
| `CHAR`    | 고정된 길이의 문자열     |
| `VARCHAR` | 길이가 변할 수 있는 문자열 |

규격화된 고정 자릿수의 데이터는 `CHAR`를 고려할 수 있고, 길이가 유동적인 데이터는 `VARCHAR`를 사용하는 것이 일반적이다.

예를 들어 주민등록번호나 사업자등록번호처럼 일정한 자릿수를 갖는 데이터에는 `CHAR`를 고려할 수 있다.

### 대용량 데이터 (LOB)

대용량의 텍스트나 파일 데이터를 저장해야 하는 경우에는 LOB(Large Object) 자료형을 사용할 수 있다.

대표적으로 다음과 같은 자료형이 있다.

```text
TEXT → 대용량 문자열
BLOB → 대용량 바이너리 데이터
```

다만 LOB 자료형은 일반적인 문자열 자료형과 달리 **인덱스 생성 등에 제약**이 있을 수 있으므로 사용 목적에 맞게 선택해야 한다.

### 인공키 (Surrogate Key)

테이블에서 적절한 기본키(PK) 후보가 존재하지 않는 경우 **인공키(Surrogate Key)** 를 사용할 수 있다.

MySQL에서는 `AUTO_INCREMENT`를 이용하여 새로운 행이 추가될 때마다 자동으로 증가하는 식별자 열을 만들 수 있다.

```sql
CREATE TABLE users (
    user_id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50)
);
```

이처럼 `user_id`를 별도의 식별자로 사용하면 데이터를 쉽게 구분할 수 있다.

### 8-2. ER 다이어그램 (ERD)

ERD(Entity Relationship Diagram)는 **엔티티(Entity) 간의 관계(Relationship)를 시각적으로 표현하는 모델링 도구**이다.

### 엔티티 (Entity)

엔티티는 데이터베이스에서 관리해야 하는 대상이다.

ERD에서는 일반적으로 사각형으로 표현하고, 내부에 해당 엔티티의 속성을 표시한다.

실제 데이터베이스에서는 하나의 엔티티가 하나의 테이블로 구현되는 경우가 많다.

### 카디널리티 (Cardinality)

카디널리티는 엔티티 간의 관계가 **몇 대 몇으로 연결되는지**를 나타낸다.

대표적인 관계는 다음과 같다.

```text
1 : 1  → 일대일
1 : N  → 일대다
N : M  → 다대다
```

### N:M 관계

관계형 데이터베이스에서는 일반적으로 N:M 관계를 직접 표현하기보다는 **교차 테이블(Bridge Table)** 을 만들어 1:N 관계 두 개로 분해한다.

예를 들어 학생과 과목의 관계가 N:M이라면 다음과 같이 구성할 수 있다.

```text
학생 1 ─── N 수강 ─── N 1 과목
```

`수강` 테이블을 통해 학생과 과목의 관계를 관리한다.

### 8-3. 정규화 (Normalization)

정규화는 데이터의 **중복을 최소화하고 데이터 무결성을 유지하기 위해 테이블을 적절하게 분리하는 과정**이다.

일반적으로 하나의 데이터가 여러 곳에 중복되어 저장되지 않도록 구조를 설계한다.

정규화는 다음과 같은 단계로 진행된다.

```text
비정규 테이블
      ↓
   제1정규형
      ↓
   제2정규형
      ↓
   제3정규형
```

### 제1정규형 (1NF)

#### 조건

하나의 셀에는 **하나의 값(원자값, Atomic Value)** 만 저장되어야 한다.

예를 들어 한 셀에 여러 개의 전화번호를 저장하는 형태는 1NF에 맞지 않는다.

```text
홍길동 | 010-1111-1111, 010-2222-2222
```

이러한 반복되는 데이터를 별도의 행이나 테이블로 분리하여 하나의 셀에 하나의 값만 저장하도록 만든다.

### 제2정규형 (2NF)

#### 조건

먼저 **제1정규형을 만족**해야 하며, **부분 함수 종속성(Partial Functional Dependency)** 을 제거해야 한다.

주로 **복합 기본키**를 사용하는 테이블에서 문제가 발생한다.

복합 기본키란 기본키가 2개 이상의 열로 구성된 경우를 말한다.

예를 들어 다음과 같은 테이블이 있다고 하자.

```text
학생ID + 과목ID → 기본키

학생ID
과목ID
학생이름
과목명
성적
```

이때 `학생이름`은 `학생ID`에만 종속되고, `과목명`은 `과목ID`에만 종속된다.

즉, 기본키 전체가 아니라 **기본키의 일부에만 종속되는 데이터**가 존재한다.

이를 별도의 테이블로 분리하여 부분 함수 종속성을 제거한다.

### 제3정규형 (3NF)

#### 조건

먼저 **제2정규형을 만족**해야 하며, **이행적 함수 종속성(Transitive Functional Dependency)** 을 제거해야 한다.

기본키가 아닌 일반 속성이 또 다른 일반 속성을 결정하는 경우가 이에 해당한다.

```text
A → B
B → C
```

위와 같은 관계에서는 결과적으로

```text
A → C
```

라는 관계가 만들어진다.

이러한 구조를 별도의 테이블로 분리하여 이행적 함수 종속성을 제거한다.

### 정규화의 장점

정규화를 통해 데이터 중복을 줄이고 데이터 수정 시 발생할 수 있는 **이상 현상(Anomaly)** 을 방지할 수 있다.

대표적인 이상 현상은 다음과 같다.

* 삽입 이상
* 갱신 이상
* 삭제 이상

데이터가 여러 곳에 중복되어 있으면 하나의 데이터를 수정할 때 여러 곳을 함께 수정해야 하는 문제가 발생할 수 있다.

따라서 데이터를 적절하게 분리하여 **데이터의 일관성과 무결성**을 높일 수 있다.

### 8-4. 트랜잭션 (Transaction)

트랜잭션은 데이터베이스의 상태를 변화시키는 **여러 작업(SQL 문)을 하나의 논리적인 작업 단위로 묶어서 처리하는 것**이다.

예를 들어 주문을 생성할 때 다음 세 작업이 모두 성공해야 한다고 가정해보자.

```text
1. 주문 정보 저장
2. 주문 상품 정보 저장
3. 주문 상품 정보 저장
```

중간에 오류가 발생한다면 일부 작업만 데이터베이스에 반영되어서는 안 된다.

이러한 상황에서 트랜잭션을 사용한다.

### COMMIT

`COMMIT`은 트랜잭션 내에서 실행한 변경 내용을 **데이터베이스에 최종적으로 반영**한다.

```sql
COMMIT;
```

커밋된 변경 사항은 트랜잭션을 종료한 이후에도 유지된다.

### ROLLBACK

`ROLLBACK`은 트랜잭션 내에서 수행한 변경 작업을 취소하고 **트랜잭션 시작 전 상태로 되돌리는 것**이다.

```sql
ROLLBACK;
```

따라서 여러 작업 중 하나라도 오류가 발생하면 전체 작업을 취소할 수 있다.

### MySQL에서 트랜잭션 사용

MySQL 클라이언트는 기본적으로 `AUTOCOMMIT`이 활성화되어 있다.

따라서 여러 SQL 문을 하나의 트랜잭션으로 묶어서 처리하려면 `START TRANSACTION`을 사용하여 트랜잭션을 시작한다.

```sql
START TRANSACTION;

INSERT INTO orders VALUES (4, '2026-10-07', 1);

INSERT INTO order_items VALUES (4, 'P0003', 1);

INSERT INTO order_items VALUES (4, 'P0004', 2);

COMMIT;
```

모든 작업이 정상적으로 수행되었다면 `COMMIT`을 통해 변경 내용을 최종 반영한다.

만약 작업 중 오류가 발생했다면 `ROLLBACK`을 실행하여 트랜잭션 내의 변경 내용을 취소할 수 있다.

```sql
START TRANSACTION;

INSERT INTO orders VALUES (4, '2026-10-07', 1);

INSERT INTO order_items VALUES (4, 'P0003', 1);

-- 오류 발생

ROLLBACK;
```

### 트랜잭션의 핵심

```text
START TRANSACTION
        ↓
 여러 SQL 실행
        ↓
   ┌────┴────┐
 정상       오류
  ↓           ↓
COMMIT     ROLLBACK
  ↓           ↓
반영        취소
```

즉, 트랜잭션은 **여러 작업을 하나의 단위로 묶어 모두 반영하거나 모두 취소할 수 있도록 하는 기능**이다.
